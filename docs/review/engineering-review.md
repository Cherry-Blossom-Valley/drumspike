Strong overall. Two flags: `style-src 'unsafe-inline'` (Tauri injects inline styles; the modern practice is to keep it only as long as the app needs it) and `withGlobalTauri: true` (tauri.conf.json), which puts the whole Tauri API on `window.__TAURI__` instead of an ES-module import — simpler for the no-bundler static/ frontend, but it widens the surface any injected script could reach. `connect-src` correctly limits to ipc.

IPC payload sizes on the hot paths (counted from the code, formula x measured constants): `peaks_tile` returns a binary Response: 12-byte header + 12 bytes per bucket (min/max/rms f32, apps/desktop/src-tauri/src/lib.rs:188-201). The finest level is bucket size 256 (PEAK_LEVELS, crates/core/src/peaks.rs:25): a full 5-minute 48 kHz track is 14,400,000 samples = 56,250 buckets = 675,012 bytes per tile (~0.64 MiB) on the initial paint path per track. `samples_window` returns 8 + 4*len bytes (lib.rs:203-217): the JS fetches the visible span plus 1 s padding per side (static/app.js:2262: start-48000, end+48000) and caps the retained cache at 900,000 samples (static/app.js:2271), so a worst-case visible-span window of 60 s is 8 + 4*(62*48000) = 11,904,008 bytes (~11.4 MiB) per call. These are binary payloads over the IPC Response path, not JSON — the right shape.

## 3. Findings (one per line: area, file:line, evidence, why it matters, refactoring, effort, risk)

- F-1 supply chain, Cargo.lock:253 (proc-macro-error 1.0.4), :348 (tokio 1.53.2), :1338 (glib 0.18.5). Evidence: cargo audit 3 warnings (§2.2), Dependabot alert 1 (rust/glib, first patched glib 0.20.0). Why: unsound/advisory-marked deps in the shipped tree; tokio is pinned =1.53.2 by apps/desktop/src-tauri/Cargo.toml so an update needs a pin bump (owner decision P3-1b style). Refactoring: bump the tokio pin to >= 1.53.3 (RUSTSEC-2026-0386 fix), plan the glib 0.18 -> 0.20 move with the GTK 0.18 -> 0.19/0.20 family (tauri 2.x tracks it upstream), document proc-macro-error as an accepted unmaintained transitive (gtk3-macros). Effort S (tokio) / L (glib family), risk low/medium (audio unaffected; GTK is Linux-shell only).
- F-2 supply chain, no deny.toml (repo root: absent, grep 0 hits). Evidence: cargo-deny default run fails on 403 licence-rejected crates; no `cargo deny/audit` in CI or justfile. Why: licence and advisory policy is not codified, so a bad crate enters silently. Refactoring: add a deny.toml (allow MIT/Apache-2.0/BSD/Unicode-3.0/Zlib, document the exceptions) and a `cargo deny check advisories bans sources licenses` step in CI. Effort S, risk low.
- F-3 dependency hygiene, Cargo.lock (67 duplicated crate names, §2.2). Evidence: `cargo tree --workspace --duplicates` counted 67 (syn x3, indexmap x3, bitflags x3). Why: compile time and binary size; several come from gtk-rs 0.18 vs tauri's newer stack. Refactoring: mostly resolves with F-1's glib family bump; re-count after. Effort M, risk low.
- F-4 lints, Cargo.toml (no `[workspace.lints]` table; grep 0 hits). Evidence: §2.1 note. Why: the pedantic baseline (316 warnings today) is not policy; nothing stops it growing. Refactoring: add `[workspace.lints.clippy]` with the groups the team wants (start: `all = "deny"`, `pedantic = "warn"`, plus `unwrap_used = "warn"` for the non-test code once F-5 lands) and drive the pedantic count to 0 in small batches. Effort S (table) + M (burn-down), risk low.
- F-5 panics, crates/app/src/export.rs:705+ (51 hits), crates/core/src/cache.rs (48), crates/core/src/io/writer.rs (45) et al. Evidence: §2.4, 525 unwrap/expect/panic outside tests. Why: a panic in the audio or export path kills the session; today the count is unknown to the build. Refactoring: convert to Result in the io/export/transport paths first (export.rs, io/writer.rs, io/atomic.rs), keep unwrap in genuinely infallible spots with an `expect("reason")`; gate with `clippy::unwrap_used = warn` scoped to non-test targets. Effort L total, ship as per-package tickets (P1-P3 below), risk medium (behaviour must stay identical: cargo test + e2e + the ENST gate per the ticket plan).
- F-6 error handling, apps/desktop/src-tauri/src/lib.rs:904-906 (`.expect("error while building the Drum Spike app")` in `run`), and the 25 async commands (lib.rs:146-474) all funnel through `blocking()` with AppError. Evidence: §2.1 missing_errors_doc/missing_panics_doc warnings. Why: the API guidelines (C-FAILURE) want `# Errors`/`# Panics` docs; the single app-level expect is a startup panic, acceptable, but undocumented. Refactoring: doc comments on the commands (mechanical), keep the one startup expect with a `# Panics` note. Effort S, risk low.
- F-7 dead code, apps/desktop/src-tauri/src/shell.rs:5. Evidence: the only default warning of a clean release build (§2.8). Why: shipped-crate warnings normalize ignoring warnings. Refactoring: remove the unused `json` import. Effort S, risk none.
- F-8 code size, crates/app/src/transport.rs (2049 lines), crates/core/src/tempo_detect.rs (1816), apps/desktop/src-tauri/src/menu.rs:833 `build` (207 lines), crates/app/src/export.rs:705 `export_all_opts` (214 lines). Evidence: §2.5. Why: the biggest review/maintenance cost centers. Refactoring: the per-package plan below (transport mixer split, menu build split into builders, export staged). Effort M/L per package, risk medium (regression checks named per package).
- F-9 Tauri capabilities, apps/desktop/src-tauri/capabilities/default.json:6 (`core:default` for all of main). Evidence: §2.9. Why: least privilege is Tauri 2's model; `core:default` is broad. Refactoring: split into a capability per concern (window/event/core read vs dialog vs drag) with explicit `allow-*` entries; verify against the `generate_handler!` list. Effort M, risk medium (a missing permission breaks a feature — gate: the e2e suite + the self-test shell slice).
- F-10 CSP/JS surface, tauri.conf.json (`style-src 'unsafe-inline'`, `withGlobalTauri: true`). Evidence: §2.10. Why: both widen the surface an injected script reaches. Refactoring: audit which inline styles Tauri/the splash actually needs (Tauri docs keep the token for injected styles) and consider `withGlobalTauri: false` with a small ESM shim if the static/ frontend can import it; low priority. Effort S/M, risk low.
- F-11 edition, Cargo.toml:12 (`edition = "2021"`, rust-version 1.90). Evidence: §2 environment + the edition guide source. Why: 2024 is the current edition; the migration is mechanical (`cargo fix --edition`, then `edition = "2024"`), and rust-version 1.90 already exceeds the 1.85 floor of edition 2024. Refactoring: one PR, `cargo fix --edition`, run the full gate. Effort S, risk low (if-let temporary lifetime changes are the only likely friction).
- F-12 build friction (this host), report #118 line 20 and this session. Evidence: without the user-tree sysroot the desktop crate cannot compile here (libdbus-sys build script fails, §2 environment); the workspace needs dbus-1/gtk dev files that the default image lacks. Why: a fresh agent or CI cannot build v0.9.6 on this host. Refactoring: bake the dev packages (libdbus-1-dev, libgtk-3-dev, libwebkit2gtk-4.1-dev, libjavascriptcoregtk-4.1-dev, libsoup-3.0-dev, pkg-config) into the host image or the agent bootstrap; the sysroot workaround stays a fallback. Effort S (image), risk none. (Docs-only change if the bootstrap is in the repo.)
- F-13 IPC hot path, apps/desktop/src-tauri/src/lib.rs:190-217 and static/app.js:2262. Evidence: §2.11 (0.64 MiB per finest peaks tile; ~11.4 MiB per 60 s samples window; JS caps at 900k samples). Why: payload sizes scale with the visible span; correct binary shape today, but the samples window has no server-side cap — the client asks for what it needs and the 1 s padding doubles the cost at span boundaries. Refactoring: none urgent; optionally clamp `samples_window` server-side to a max window and document it. Effort S, risk low.
- F-14 concurrency shape, crates/app/src/transport.rs:614/885/971 and apps/desktop/src-tauri/src/lib.rs:66-75. Evidence: §2.12. Why: none — this is the shape the Tauri docs recommend (async commands + spawn_blocking for blocking work). Recorded as a positive: no refactoring needed.
