# AI, ML and agentic ideation for Drum Spike, including UI and UX

Ticket #122 (owner request 2026-10-29). A docs-only report: no code changes.

Standing owner decisions on record: the DSP detector is the product (2026-10-23); a model is
an option, not the default, and a model idea must say how it beats or helps the DSP path and
what it costs. The ADTOF model licence is not cleared for commercial use. The app runs
locally; anything that sends audio or project data off the machine says so and is opt-in.
Test data (the owner's sessions, ENST, STAR) is internal only; this report uses aggregates
from the merged campaign reports only (docs/review/test-campaign-0.9.6/) and
docs/review/detector-plan.md.

Evidence anchors used below: #116 (Session A-C detection, Learn, review queue), #118 (ENST
stress, tempo), #119 (STAR full-kit and mix), detector-plan.md (packages 1-8, #77, #98
probes). Aggregates only; no file, song or take names.

## Ranked top 5

1. **Review-queue ranking and explain-why (#1 + #2).** The detector already computes and
   stores per-candidate gate verdicts; `track_confidence` ignores them (detector-plan
   package 4). Threading them into the confidence and the `why` string is a small change
   with no detection impact, protected by the parity gate, and it upgrades two surfaces at
   once: the queue ranks by cause, and every hit explains itself. It is pure DSP, no model,
   no licence, fully local, and the evidence is measured (130 queued of 2413 kept, #116).
   This is the highest value per line of code in the list.

2. **Bleed guard on the tom mics (#4).** The worst measured detection defect in the corpus
   is drummer_3 tom bleed: F1 0.407 with 2.2-3.3x over-firing, an estimated ~0.3 F1 lift
   from a guard, and the per-mic bleed table needed for the rule already exists in the
   score (#118). A DSP rule first keeps the product decision honest; a classifier is only
   the fallback if a rule cannot separate. The gate that can fail is already defined
   (within 2 % of baseline, bounded recall loss).

3. **Detect once, classify per hit (#5).** The full-kit and mix cases fail on role
   separation, not on time: tom P 0.14, cymbal 0.17, and kick precision collapses to 0.25
   with music (#119). One multi-class pass over existing features is the change #119 names
   as the fix for both checks. It is the most expensive idea here (L effort, on-device
   size/speed/energy cost, own training data because ENST and STAR are NC-licensed), so it
   ships only if the prototype beats the DSP path on the same corpus — the experiment can
   fail, and that is the point.

4. **"Check my session" agent report (#10), with batch over folders (#22).** Every number
   the report needs exists locally today (doubtful hits with reasons, tempo stability, role
   confidence), and the campaign proved the CLI runs unattended over 100+ sessions. This
   turns Drum Spike into something an agent can operate through MCP/CLI (#120) with no new
   model, no licence question and a read-only default. The experiment fails loudly: the
   report must reproduce #116's counted 130 queued hits.

5. **Cross-project Learn This / Forget This (#3).** The per-track correction mechanism is
   already measured clean — 16 added with 0 false adds, 90 removed with 0 false removes
   (#116 check 3) — but it forgets everything between projects. Persisting correction
   templates per role, with an explicit apply step and a Forget all, is a modest ML use of
   the user's own data, fully local, and the held-out replay experiment can fail before it
   ever ships.

## Rejected ideas, with the reason

| Idea | Reason |
|---|---|
| Per-track self-calibration from the track's flux statistics | Measured and rejected in #77: no statistic is stable — snare q10 degenerate at 0, kick pk spread ~900x; the working point cannot be derived silently. The idea survives only as the explicit sensitivity suggestion (#12) |
| A per-candidate learned cut for the kick false keeps | Measured and rejected in #98: the best cuts remove at most 1 of 52 session false keeps while paying 24-28 true keeps; the false keeps sit where the true keeps sit on every measured dimension. Survives only as the session-level variant (#21), with the overlap as the prior |
| ADTOF or any external pretrained detection model as the product default | Licence not cleared for commercial use (owner decision); also contradicts the DSP-is-the-product decision of 2026-10-23. A model idea must justify itself against DSP (#5 is the one that does) |
| Cloud detection or cloud separation as the default path | The app runs locally (owner constraint). Any off-machine audio path is opt-in and marked; #23 keeps the cloud variant behind explicit opt-in and the local flag first |
| Tempo reference derived from MIDI headers of test material | Measured as a placeholder: every STAR test-split MIDI carries the constant default 120 BPM, so 30/31 "differ" from a reference that is not a reference (#119 check 4). A real reference needs beat annotations or per-song metadata, which is a data task, not a product idea |
| Fully generative UI (the LLM draws or edits the review screen) | No measured evidence of a problem; high risk of a wrong edit on the user's project; the doubt data is structured and the flows in #14/#15 solve the same friction deterministically |
